# Upload security

Administrator business and advertisement uploads accept JPEG, PNG and WebP files that pass server-side checks. Laravel validates the server-detected MIME type, the allowed extension, image metadata, container ending, a 5 MB size limit, dimensions up to 10,000 by 10,000 pixels and a 25 million pixel limit. Client `accept` attributes and Content-Type headers are not trusted. Stored names and directories are generated by Laravel under `storage/app/public/businesses/{id}` or `storage/app/public/advertisements/{id}`.

Uploads are served through the existing public storage link as static files. The application never includes uploaded files as PHP source. On Apache, keep script execution disabled in the storage directory, for example:

```apache
<Directory "/path/to/backend/storage/app/public">
    Options -ExecCGI
    RemoveHandler .php .phtml .php3 .php4 .php5 .phar
    RemoveType .php .phtml .php3 .php4 .php5 .phar
</Directory>
```

On Nginx, serve `/storage/` as static content and do not pass it to PHP-FPM. Keep the storage directory outside the application source tree where the deployment layout allows it. The normal Laravel administrator authorization still protects upload, replacement and deletion endpoints.

Malformed images covered by the current checks, scripts renamed as images, SVG, HTML, oversized files and files with unsupported extensions are rejected. PNG, JPEG and WebP container endings are checked so trailing data is rejected. This local PHP environment has `fileinfo` but no GD or Imagick; uploads are checked through MIME detection, image metadata and container structure, but are not fully decoded or re-encoded. A production web server still needs to be checked separately for static serving and disabled script execution. Failed writes remove their temporary stored file. Existing demo SVG artwork remains outside these upload directories and is not deleted by replacement cleanup.

For local XAMPP testing on Windows, ensure the PHP process that serves requests has a writable `upload_tmp_dir`. A blocked `C:\xampp\tmp` caused PHP to prepend an upload warning to an otherwise successful JSON response, so the browser reported an unreadable response. Retesting with the built-in PHP server and a writable temporary directory returned clean JSON. Changing the option only on the parent `php artisan serve` command does not pass it to the child server process; configure the serving process itself or the PHP configuration used by it.
