# Upload security

Administrator business and advertisement uploads accept only genuine JPEG, PNG and WebP files. Laravel validates the server-detected MIME type, the allowed extension, image decoding, a 5 MB size limit, dimensions up to 10,000 by 10,000 pixels and a 25 million pixel limit. Client `accept` attributes and Content-Type headers are not trusted. Stored names and directories are generated by Laravel under `storage/app/public/businesses/{id}` or `storage/app/public/advertisements/{id}`.

Uploads are served through the existing public storage link as static files. The application never includes uploaded files as PHP source. On Apache, keep script execution disabled in the storage directory, for example:

```apache
<Directory "/path/to/backend/storage/app/public">
    Options -ExecCGI
    RemoveHandler .php .phtml .php3 .php4 .php5 .phar
    RemoveType .php .phtml .php3 .php4 .php5 .phar
</Directory>
```

On Nginx, serve `/storage/` as static content and do not pass it to PHP-FPM. Keep the storage directory outside the application source tree where the deployment layout allows it. The normal Laravel administrator authorization still protects upload, replacement and deletion endpoints.

Malformed images, scripts renamed as images, SVG, HTML, oversized files and files with unsupported extensions are rejected. PNG, JPEG and WebP container endings are checked so appended non-image data is rejected. This deployment currently has `fileinfo` but no GD or Imagick; uploads are decoded and structurally checked, but are not re-encoded. Adding a re-encoding library would be a separate hardening decision. Failed writes remove their temporary stored file. Existing demo SVG artwork remains outside these upload directories and is not deleted by replacement cleanup.
